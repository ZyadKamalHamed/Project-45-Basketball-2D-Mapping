# CoutIQ - Basketball 2D Mapping & Statistical Analysis  

End-to-end basketball video analysis: detect players and the ball, track them across
frames, project their positions onto a top-down court, identify the two teams from
jersey appearance, and detect shot events with made / missed classification. The
result is rendered in a dashboard with the original game footage, a 2D shot map,
team-level stats, and a shot log.

**Team:** Zyad Hamed (Court Vision Mapping), Abdelrahman Ramadan (Player Detection +
Team Clustering), Ilias Sleiman (Shot Detection).

## How the pieces fit together

```
Uploaded video ─> analyze.py ─> pipeline/* ─> results.json ─> GUI dashboard
```

The bridge loads the trained weights produced by the
notebooks and calls the same functions the notebooks demonstrate. The GUI never
calls a model it only renders the JSON the bridge writes.

## Running it

### Path 1: Reproduce the ML work on SageMaker 

Weights from previous runs are saved under weights/*. alternatively is a user prefers to start training these models themselves from scratch, all three notebooks under `notebooks/` were written for SageMaker JupyterLab with a
GPU instance to reproduce the training and inference inside the notebooks. The steps are as follows:

1. Open SageMaker JupyterLab.
2. Clone this repo into the SageMaker workspace.
3. Open a notebook from the `notebooks/` folder. Set the working directory to the
   project root (the notebooks reference paths like `Data/...`, `weights/...`
   relative to the repo root, not their own folder).
4. Run each notebook's setup cell once — it installs `ultralytics`, `supervision`,
   and the `roboflow/sports` library (the basketball branch).
5. Each notebook downloads its dataset on first run (datasets are gitignored).
6. Training runs produce `.pt` weight files under `weights/runs/` and
   `weights/runs_abdo/`.

### Path 2: Run the full pipeline + dashboard locally

Once the trained `.pt` files exist, the bridge can analyse any video on your
machine. You'll need:

- Python 3.12 + a venv with `requirements.txt` installed.
- Node.js 20+ + `npm install` inside `GUI/`.
- `ffmpeg` on the system PATH (for re-encoding the annotated video to H.264 so it
  plays in browsers).
- The trained weights at the paths the bridge expects:
  - CVM pose model: `weights/runs/CVM_Best.pt` (or override with `CVM_MODEL_PATH` env var).
  - Player detector: `weights/runs_abdo/Player_detection.pt` (or `PLAYER_MODEL_PATH`).

Start the dashboard:

```bash
cd GUI
npm install
npm run dev
```

Open `http://localhost:3000`, upload an MP4 of a basketball clip, wait ~40 seconds
on CPU (or ~5 seconds on GPU), and you'll see:

- The video with team-coloured detection boxes overlaid 
- A 2D shot map with O for makes / X for misses.
- Two team stat cards: shots, makes, FG%, 3P%, 2P%, points.
- A shot log table

## Environment overrides

| Env var | Purpose |
|---|---|
| `CVM_MODEL_PATH` | Override the path to the CVM pose model weights. |
| `PLAYER_MODEL_PATH` | Override the path to Abdo's 6-class detector weights. |

These let the same `scripts/analyze.py` run on SageMaker (different filesystem
layout) without any code changes.

## Browser playback note

The video player in the dashboard uses HTML5 `<video>`. If your test clip is encoded
with MPEG-4 Part 2, HEVC, or another codec the browser doesn't ship, the GUI will
show "Browser can't play this file" where the video would be — but the analysis
still runs and the shot map / stats / log still populate. To preview the video too,
re-encode the clip to H.264 with `ffmpeg`:

```bash
ffmpeg -i input.mp4 -c:v libx264 -preset fast -crf 23 \
       -pix_fmt yuv420p -movflags +faststart output-h264.mp4
```
